# Блочная IDE q.bit: как всё устроено

Открыть: `ide/index.html` двойным щелчком (или `node ide/tools/serve.js`; одним файлом: `python -X utf8 ide/tools/build.py` → `ide/dist/qbit-ide.html`). Симулятор платы без редактора: `ide/simulator.html`.

## Идея в одной схеме

```
   БЛОКИ ──генератор──►  PYTHON (текст)  ──Запустить──►  УСТРОЙСТВО
 (Blockly)              import qbit …                      │
                        qbit.led(3).on()          ┌────────┴─────────┐
                                                  ▼                  ▼
                                       СИМУЛЯТОР в браузере     НАСТОЯЩАЯ ПЛАТА
                                       pyinterp.js (Python)     MicroPython
                                       runtime.js  (qbit)       mpy/qbit.py
                                       contract.js (драйверы)   _qbit → firmware/qbit_core
                                       core/*  (железо)         железо
```

Главное решение: **один текст программы** запускается и в симуляторе, и на плате. Блоки лишь удобный способ написать этот текст, а вкладка «Python» показывает его честно (это же и ступенька к настоящему программированию). Поэтому не бывает «в симуляторе работает, а на плате другой код».

## Что с чем связано

| Слой | Файлы | Что делает |
|---|---|---|
| **Контракт** | `js/runtime/spec.js` | единственный список: что у каждого из 33 модулей можно прочитать (значения), приказать (команды) и услышать (события). Имена те же, что в драйверах прошивки (`firmware/qbit_core/drivers/*.c`); тест сверяет их с C-кодом |
| **Блоки** | `js/ide/catalog.js`, `blocks.js`, `toolbox.js` | каталог блоков по модулям → блоки Blockly и генератор Python. Блок может вызвать только то, что есть в контракте (проверяется тестом) |
| **Редактор** | `js/ide/editor.js` | Blockly с темой макета: подсветка выполняемого блока, предупреждения «на порту нет такого модуля», сохранение |
| **Исполнение в браузере** | `js/runtime/pyinterp.js`, `contract.js`, `runtime.js` | интерпретатор Python (сверен с CPython), «драйверы прошивки» поверх моделей модулей симулятора, модуль `qbit` |
| **Исполнение на плате** | `mpy/qbit.py`, `mpy/qbit_spec.py` | то же самое для MicroPython; таблица генерируется из `spec.js` |
| **Устройства** | `js/ide/device.js`, `link.js` | единый интерфейс «устройство»: симулятор, плата по Wi-Fi, плата по USB |
| **Протокол** | `docs/PROTOCOL.md`, `tools/fake-board.js` | как IDE говорит с платой; поддельная плата для проверки без железа |
| **Оболочка** | `index.html`, `css/ide.css`, `js/ide/ide.js`, `panes.js` | верхняя панель, вкладки, консоль, устройства, данные, примеры, проект |

## Что происходит при «Запустить»

1. Блоки превращаются в Python (`Q.Blocks.generate`): под каждым «когда …» своя `async def`, после цикла `await qbit.tick()`, паузы — `await qbit.wait(...)`. Блоки не под «когда …» не запускаются (как в Scratch) и помечены предупреждением. Вместе с текстом строится карта «строка → блок».
2. Текст уходит в выбранное устройство. **Симулятор:** интерпретатор запускает программу как набор кооперативных задач, время идёт в такт модели платы (`ждать 1 секунду` — это секунда симуляторного времени). **Плата:** по сообщению `run` (см. протокол), дальше MicroPython.
3. Устройство присылает номера выполняемых строк (подсветка блока), `print` (консоль), ошибки (текст по-русски, блок с ошибкой подсвечен красным), состояние портов (вкладка «Данные», предупреждения на блоках) и питание.

## Плата и симулятор рядом

- В «Устройствах» выбирают, где запускать. Симулятор всегда есть; настоящая плата появляется, когда к ней подключились (адрес Wi-Fi, USB или IDE, открытая прямо с платы: тогда подключение само).
- Пока плата активна, картинка справа **повторяет её** (модули, кнопки, светодиоды, серво). Когда плату отключили, симулятор возвращается к своей сцене.
- Блок «светодиод порт 3» не знает, где он будет работать: порт — это номер, а модуль проверяется в момент вызова. Если там другой модуль, программа останавливается с понятной ошибкой («на порту 1 стоит «Кнопка», а программа ждёт «Светодиод»»), блок краснеет.
- Выпадающий список портов подписывает порты тем, что на них стоит (`порт 3 ●` — здесь нужный модуль), а панель блоков сначала показывает блоки подключённых модулей.

## Известные отличия симулятора от платы

| Что | Как в симуляторе | Как на плате |
|---|---|---|
| целые и дробные числа | и те и другие — числа JS: `6 / 3` печатается `2` | `2.0` (CPython и MicroPython различают) |
| время | модель платы идёт в реальном времени | реальное; тайминги датчиков по даташитам |
| классы, `try/except`, генераторы | не поддерживаются (понятная ошибка) | есть в MicroPython |
| `time.sleep` | запрещён (сообщение: «используйте `await qbit.wait`») | блокирует всё; в блоках не используется |
| значения датчиков | модель с шумом и задержками, но не заменяет проверку на железе | настоящие |

## Как добавить модуль или блок

1. Драйвер в прошивке и модель в `js/core/modules/*` уже есть для 33 модулей. Если нужен новый **модуль**: поля, команды, события — в `js/runtime/spec.js` (названия как в драйвере); драйвер симулятора — в `js/runtime/contract.js` (`DRIVERS.<ключ>`); запустить `node ide/tools/gen_qbit_spec.js` и `node ide/tools/gen_api_doc.js`.
2. Новый **блок**: запись в `js/ide/catalog.js` (текст, аргументы, шаблон Python); тест `tests/ide.test.js` сам проверит, что шаблон вызывает существующее.
3. Примеры: `js/ide/examples.js`.
4. Каждый видимый текст — по-русски в `T('…')` (в `catalog.js`, `spec.js`, `examples.js` тоже); переводы — в `js/i18n/en.js` и `uz.js` (`node ide/tools/i18n_keys.js --missing` покажет недостающие).
5. `node ide/tests/run-all.js`.

## Тесты

| Команда | Что проверяет |
|---|---|
| `node ide/tests/run-all.js` | всё подряд (около 1,5 минуты; `--quick` — без браузера) |
| `tests/core.test.js` | плата, 33 модуля, паспорта, питание |
| `tests/py.test.js`, `conformance.test.js` | интерпретатор Python; и что он печатает то же, что настоящий CPython (`tests/corpus/*.py`) |
| `tests/runtime.test.js` | контракт против C-драйверов, программы на плате симулятора |
| `tests/mpy.test.js` | модуль `qbit` для MicroPython на CPython |
| `tests/link.test.js` | протокол с платой (поддельная плата) |
| `tests/browser.test.js` | блоки и генераторы в Chrome |
| `tests/i18n.test.js` | словари `en` / `uz` полные, `%1 %2` на месте, лишнего нет |
| `tests/ui.test.js` | IDE целиком: пустой проект при первом запуске, раскладка (переключатель, поиск, колонка кнопок, отступы от краёв, корзина принимает блок), запуск, пауза, ошибка, поиск, комплект, телефон, плата по сети; колонка категорий без прокрутки; нет теней и эмодзи; на английском и узбекском не остаётся русского текста |
