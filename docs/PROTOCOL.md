# Протокол IDE ↔ плата

Как редактор блоков разговаривает с настоящей платой. Со стороны IDE это `js/ide/link.js`, эталон стороны платы — `tools/fake-board.js` (работает уже сейчас, на нём проверяется `tests/link.test.js`). Прошивка реализует то же самое поверх MicroPython и модуля `qbit` (`mpy/qbit.py`).

## Транспорты

| Путь | Как | Когда |
|---|---|---|
| **Wi-Fi** | WebSocket `ws://192.168.4.1/ws`, одно JSON-сообщение на кадр | основной: телефон, планшет, компьютер без установки |
| **USB** | Web Serial (115200), одно JSON-сообщение на строку (`\n`), строки не из JSON игнорируются | Chrome / Edge на компьютере; обновление прошивки |

Плата сама раздаёт IDE: `GET /` отдаёт `qbit-ide.html.gz` (`tools/build.py`), `GET /qbit.json` → `{"qbit":1,"name":"q.bit-4F2A","fw":"0.1.0","ws":"/ws"}`. Если IDE открыта с платы (`http://…`) и этот адрес отвечает, IDE подключается сама. Если страница открыта по `https://`, браузер запретит `ws://`: IDE должна открываться с платы или локально.

## Сообщения

JSON-объекты, поле `t` — тип.

### IDE → плата

| Сообщение | Что значит |
|---|---|
| `{"t":"hello","v":1,"client":"qbit-ide"}` | первое сообщение; в ответ `hello` и `state` |
| `{"t":"run","code":"…"}` | остановить текущую программу и запустить эту (текст Python) |
| `{"t":"stop"}` / `{"t":"pause"}` / `{"t":"resume"}` | управление программой |
| `{"t":"cmd","port":3,"words":["brightness","50"]}` | одна команда модулю, как в консоли (кнопки «Проверка выходов») |
| `{"t":"ping"}` | проверка связи |

### плата → IDE

| Сообщение | Что значит |
|---|---|
| `{"t":"hello","v":1,"fw":"0.1.0","name":"q.bit-4F2A","board":"qbit-main-revB"}` | ответ на `hello` |
| `{"t":"state","ports":[…],"power":{…},"run":{"status":"running"}}` | состояние платы: раз в 200 мс и сразу при изменениях |
| `{"t":"print","text":"привет\n"}` | то, что программа вывела (`print`) |
| `{"t":"error","type":"QbitError","message":"…","line":7}` | ошибка программы (после неё программа остановлена) |
| `{"t":"status","status":"running"}` | `running`, `paused`, `finished`, `stopped`, `error` |
| `{"t":"line","n":7}` | номер выполняемой строки (не чаще 20 раз в секунду; нужен для подсветки блока; можно не слать) |
| `{"t":"pong"}` | ответ на `ping` |

**`ports`** — всегда 8 элементов, по порядку портов:

```json
{ "n": 3, "key": "led", "title": "Светодиод", "state": "ready", "values": { "brightness": 100 }, "text": "green" }
```

`key` — ключ модуля из `js/runtime/spec.js` (`null`, если порт пуст), `state` — `empty | debounce | ready | unknown | fault | nobudget | covered` (двойной модуль занимает два порта: на втором `covered`), `values` — значения в точности как их публикует драйвер прошивки (имена — поле `n` в `spec.js`, у светодиода это `brightness`), `text` — текстовое значение (цвет светодиода, UID метки RFID).

**`power`**: `battery` (%), `usb`, `charging`, `volts`, `amps`, `source` (текст).

## Что обязана делать плата

1. **Программа — это текст Python.** Плата выполняет его на MicroPython с модулем `qbit` и ничего не знает про блоки. Тот же текст в симуляторе даёт то же поведение; расхождения — это ошибки симулятора или прошивки.
2. **Ошибка останавливает программу**, плата присылает `error` с номером строки (по трассировке) и `status: error`. Строки считаются по тексту, который прислала IDE.
3. **Безопасное состояние.** При `stop`, ошибке и сбросе платы светодиоды, RGB, зуммер, мотор и реле выключаются (таблица `SAFE` в `mpy/qbit_spec.py`). Когда программа просто закончилась (`finished`), выходы остаются как есть.
4. **События.** Если скрипт-обработчик ещё работает, новое такое же событие пропускается (правило и в симуляторе, и в `mpy/qbit.py`).
5. **Связь не нужна для работы.** Если IDE отключилась, программа продолжает работать; при новом подключении плата присылает `hello` и `state` (в том числе `run.status`).
6. **Одна программа.** `run` от второго клиента заменяет программу первого (побеждает последний); это решение принято для простоты и его можно ужесточить, когда появятся пользователи с несколькими планшетами.

## Зеркало платы в IDE

Пока настоящая плата — активное устройство, картинка платы справа показывает её копию: модули из `ports`, нажатия кнопок, яркость светодиодов, положение серво и т. д. (см. `MIRROR` в `link.js`). Перетаскивание модулей на картинку в это время отключено: модули ставят на настоящую плату. Когда выбирают симулятор, его сцена возвращается как была.

## Проверка без железа

```bash
node ide/tools/fake-board.js --port 8780 --modules button:1,pot:2,led:3,rgb:4
```

Откройте `http://localhost:8780/` — IDE подключится сама. «Потрогать» плату: `GET /touch?port=1&key=pressed&value=1`, посмотреть, что она сообщает: `GET /state`.
